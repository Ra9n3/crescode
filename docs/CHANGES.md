# Smart Chord Suggestion

## Foundation layer (engine/suggestion)

- Data contracts (`types.ts`) + the DAW adapter interface (`adapter.ts`): ticks at 960 PPQ are the only timeline unit; seconds exist only as a derived display value. Chord names validate exclusively through the shared `parseChord` — one grammar, never two.
- MIDI parsing (`parse.ts`): weighted pitch-class analysis (`weight = soundingDuration × velocity × bassBoost × beatBoost`) over every root × template derived from the shared parser; `score = matched − missing − unexpected`, an absent third costs 1.5 for extended templates, slash readings ("G/C") are labelled instead of penalized, bass is a hint never an automatic root. Returns status (clear / ambiguous / incomplete / unknown), confidence 0–100, alternatives, matched/missing/extra pitch classes. Key context and neighbouring chords only break ranking ties — never the verdict.
- Enharmonic engine (`enharmonic.ts`): explicit per-pitch-class spelling tables (C♯/Db … Cb=B, E#=F, B#=C, Fb=E) — no single global conversion rule anywhere.
- Normalization (`normalize.ts`): `normalizeChord(root, projectKey)` picks the key-idiomatic spelling (Db → C# in D major, C# → Db in Eb major, Bb in F major, C# kept over a D-minor signature as the raised leading tone) without ever changing the pitch class.
- DAW state reader (`context.ts`): `readChordContextAt(api, time)` returns previous/current/next clips with fresh analyses; read-only.

## Interaction layer (this change)

- Host adapter (`host.ts`): the concrete `ChordTrackAPI` over the app's own model. Chord clips are views over `project.chords`; their MIDI lives on the Chords structure track (`role: "chords"`), whose notes are inert (never played, exported or generated). A chord-lane MIDI clip is persisted as a lane event with the `sch_` id prefix and starts with the key tonic as its placeholder symbol; session-only MIDI clips on instrument tracks use a registry rolled back on cancel. Transactions ride the store's snapshot history: commit = one undo entry, cancel restores project and dirty flag exactly. Unparseable (mid-edit) symbols are excluded from clip views but still bound gaps. The double-click emitter ships with the adapter (`subscribeToDoubleClick` / `emitDoubleClick`).
- Interaction logic (`interaction.ts`): `planClipPlacement` implements the span rules on the native grid — exactly 1 bar → 1 bar; less (but ≥ one grid unit) → exactly fills the gap; more → 1 bar and the rest stays empty; smaller than one grid unit → too small (warning, nothing created); the start snaps down to the grid, clamped into the gap; open tail gaps count as "more than 1 bar". `DoubleClickGate` drops same-tick repeats inside a 350 ms cooldown. The controller wraps creation in one "Create Smart Chord Clip" transaction, writes the empty/root-note placeholder per user preference, opens the editor with the created clip id, and cancels back to the pre-gesture state on any failure.
- Double-click conversion: the first click of a double-click on empty space still runs crescode's manual-chord creation (protected workflow). When the double-click lands on that just-created chord (freshness tracker in `wire.ts`, 450 ms window), the gesture removes the false start inside the same transaction that creates the Smart clip — one undo step net, and the manual chord is restored if creation fails.
- Chord editor (`ChordEditor.tsx`): the panel opened by the gesture — symbol input validated live through the shared parser, primary reading with confidence meter and status chip, alternative readings (click to name the clip), matched/missing/extra pitch-class chips, notes/bass line, and the persisted new-clip preference (Empty / Root note). Renames go through `renameChordClip` transactions that preserve id, position, length and metadata; Delete works via the existing selection shortcut.
- Store: `suggestionClipId` (the clip the editor has open — read by the suggestion UI and MIDI injection) and `settings.smartChordPlaceholder` (persisted).
- New store state does not touch the schema: `project.chords` and `Track.notes` carry everything, so save/export/reload keep working unchanged. Tests: `tests/suggestion-interaction.test.ts` (36) + `scripts/e2e-chord-gesture.mjs` (`npm run e2e:gesture`, 10 browser checks) beside the existing suites.

## Background engine (engine.ts, shipped before this change)

- The pure engine behind the overlay: a bounded candidate vocabulary (12 roots × 20 shapes through the shared grammar, tiered by the complexity preference), transparent 0–100 scoring with the spec's rule weights (diatonic fit, strong functional relations and resolutions, common tones, fifth motion, borrowed/modal bonuses, tritone/third clash and near-duplicate penalties), per-root diversity caps with a 12–24 output window, §4 ambiguity handling (the primary reading ranks first, each ambiguous neighbor gets one secondary ranking, materially moved suggestions are flagged context-sensitive, ambiguity is stated on every suggestion, never hidden) and the deterministic §5 color bands (75–100 green / 45–74 yellow / 0–44 red). `suggestChordsAt(api, time)` reads key, grid, gap and neighbors off the adapter; `chordSuggestionsAt(time)` in `wire.ts` is the app-bound entry the overlay calls.

## Floating overlay (this change)

- MIDI voicing (`voicing.ts`): turns a chord symbol into exact MIDI note values under the spec's rules. The default octave is centered near C4 by a documented rule — among every octave the bass may start in, the stack whose median sits closest to the anchor wins (ties to the lower bass); close voicing stacks the chord tones by shortest interval from the bass, so inversions and slash basses voice correctly (C/E → E3 G3 C4, G/B → B3 D4 G4); the bass is the lowest tone by construction; notes outside MIDI 36–84 are avoided unless an explicit octave offset (C2–C6 select) requests otherwise; one note per pitch class (the shared parser dedupes); the bass keeps the chord's own normalizeChord spelling, remaining tones use crescode canon. Clip bounds are caller-supplied — start time and duration are never decided here. Pure and deterministic.
- Overlay logic (`overlay.ts`): the dropdown tables and the Apply write path as testable functions. Extension choices are a fixed suffix table per triad base, gated through the shared parser and deduped by sound — the user's root and quality are preserved unless the extension makes them invalid (min7/m6 force minor, dim7 forces diminished, sus replaces the third, power replaces the shape); bass choices are Auto (keep the analyzed slash), Root position and the chromatic notes labeled as inversions or slash bass, normalized through normalizeChord for the project key (Db in Eb major, Bb in F major); buildChordSymbol composes root + suffix + slash and verifies the pitch class never moved. clipDrift backs the non-destructive Apply rule (missing / moved / renamed / edited). applyChordToClip re-locates the clip, guards the drift, then replaces notes and renames inside ONE "Apply Smart Chord" transaction, canceling back on any failure.
- The overlay UI (`ChordSuggestions.tsx`, hosted by `ChordEditor.tsx`): floating, non-blocking (no backdrop, the DAW stays interactive). Chord grid — chord name prominent, spec color bands as card backgrounds, the human explanation as a secondary line with reason codes, breakdown and alternative-context results on hover, engine ambiguity (a neighbor reading two ways) marked on the affected cards, engine-score order with search (symbol/quality) and color-band filters plus a Score/Name sort. Customization — Bass note / Extension / Octave selects derived from the selected card (reset on selection, defaults reflect the chord itself), with the live preview recalculating the composed name and the exact MIDI notes immediately. Apply — the extracted transaction above, then close or minimize per the persisted `settings.smartChordApply` preference; a drifted clip warns non-destructively and is never overwritten. The parent's minimize toggle collapses the overlay to its header; all previous editor behavior (symbol rename, analysis, alternatives, placeholder preference, Esc) is unchanged.
- Store: `settings.smartChordApply` ('close' | 'minimize', persisted beside smartChordPlaceholder); Select/Button gained optional testId props.
- Tests: `tests/suggestion-overlay.test.ts` (35 — voicing rules, control tables and round-trips, drift guard, the apply transaction through the real host adapter, engine → overlay chain) and six new browser checks in `scripts/e2e-chord-gesture.mjs` (grid/colors, search, color filter, dropdowns with live preview, apply close/minimize, moved-clip warning) — 19 checks total there, full suite 211 unit + 41 smoke.
