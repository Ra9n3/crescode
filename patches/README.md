# Separated patches

Changes that are kept **separately identifiable** from the main Phase 1 work, so
each can be reviewed, reverted or landed on its own terms. Status is stated per
patch — check it before assuming one is or is not in the tree.

## `0001-strings-voice-ceiling.patch`

**Status:** **APPLIED** to `src/compose/families/strings.ts` in the delivered
tree. It is kept here so the change remains separately identifiable, reviewable
and reversible:

```
git apply -R patches/0001-strings-voice-ceiling.patch   # revert it
```

The patch still applies cleanly *in reverse* to the delivered tree (verified),
and was verified to apply cleanly forward to the pre-patch tree.

**What it fixes.** `pitchForPitchClass` in `src/compose/families/strings.ts`
documents its ceiling as a hard invariant — "a lower voice must never rise above
the lead" — but computed it as
`Math.max(winLow + 11, Math.min(winHigh, ceiling))`. The `Math.max` silently
raised the ceiling back to a full octave whenever the requested ceiling left
fewer than eleven semitones, so an inner voice bounded under a lead at 68 could
still be placed at 72. Two paths compounded it: the inner-voice call site passed
only the static `leadFloor - 1` (never a per-instant ceiling), and the
`avoidLeadCollision` nudge that runs afterwards was called without the ceiling,
so it could lift the note back above the lead the clamp had just put it under.

**Measured effect** — `dorian-16bars`, seed 1, violins2 above violins1,
120-tick sampling:

| State | Crossings | Bars |
|---|---:|---|
| Baseline: no pairing, no fix | 32 | 6, 8 |
| Delivered Phase 1 tree: pairing, no fix | 64 | 6, 7, 8 |
| Delivered: pairing + this patch | **0** | — |

`three-chorus-40bars` is 0 in all three states; the defect is latent there and
only surfaces where the melody descends to 64 under a sustained inner voice.

**Independence.** The defect exists with the pairing feature reverted (32
crossings), so it predates the Phase 1 correction. Applying the patch changes
only violins2: the lead's pitches, motif IDs, statement operations and the
0-tick section boundary are byte-identical with and without it, and acceptance
test `3b` passes in both states. The pairing's contribution to the count
(32 → 64) is a consequence of the antecedent being longer, not a new defect.

**Why it is carried separately.** It is a genuine correctness bug — the code
contradicts its own documented invariant — but it changes inner-voice pitch
selection outside the cross-section correction's scope. It was first held back
for independent review, then explicitly approved and applied as a closeout step.
It is documented in report §8.11 and guarded by
`tests/compose/strings-ceiling.test.ts`, whose three tests **fail on the
pre-patch code** (264/1680 placements above ceiling; worst pitch 61 against a
requested 52).

**Verification on the delivered tree.** `tsc` 0 errors; `tests/compose/` 64/64;
full suite 17 failed / 1271 passed with the same 11 pre-existing failing files
and no legacy golden re-pinned; `vite build` ✓ 4.03 s; dorian and three-chorus
both at **0** voice crossings; both cross-section pairs intact.

**How it was produced.** The patch was generated by diffing the Phase 1 tree
against the tree with the fix applied, then verified to apply cleanly and
reproduce the fixed file byte-for-byte. It is not a transcription.
